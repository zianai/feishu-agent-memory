# Token / 字符预算

> 字符≈token 的简化：中文场景 1 token≈1~1.5 字符，用字符预算近似控制，超剪策略一致。
> 数值沿用参考文章（得物技术四层记忆架构）的工程参数。

| 项 | 预算 | 超预算处理 |
|---|---|---|
| 长期记忆总注入 | 4000 token（约 4000 字符） | 从重要度最低的开始丢 |
| 其中：用户画像 | ≤ 60%（2400 字符） | — |
| 其中：Agent 经验 | ≥ 40%（1600 字符） | — |
| 单条记忆 | 截断至 1000 字符 | 直接截断 |
| 粗筛候选 | ≤ 30 条（重要度降序） | — |
| 精排后注入 | 未指定时取前 10 条 | — |
| 滚动摘要 | ≤ 800 字符 | 重写时压缩 |
| 短期窗口 | 最近 20 条起步，从新到旧装填 | 超出总上下文预算即停 |

## 装填顺序（读链路拼 Prompt）

```
system:  prompts/system.txt（含 USER_MEMORIES / AGENT_MEMORIES / SUMMARY）
user:    SHORT_TERM（近期对话）+ 当前问题
```

用户画像优先级高于 Agent 经验：两者争预算时先保用户画像（60/40 由 config.env 控制）。
